1. DESCRIPCIÓN GENERAL
================================================================================

KOA es una aplicación móvil multiplataforma de monitoreo de bebé desarrollada
con Flutter. Combina registro de actividades del bebé, monitor de cámara IP
remoto, biometría facial, notificaciones locales y un sistema de puntos de
lealtad. El backend es gestionado por Supabase (PostgreSQL + Auth + Storage).

--------------------------------------------------------------------------------
1.1 OBJETIVOS TÉCNICOS
--------------------------------------------------------------------------------
  - App nativa Android (arm32 / arm64) e iOS (15.5+)
  - Autenticación segura con Supabase Auth (JWT)
  - Reconocimiento facial on-device con MobileFaceNet + TFLite
  - Monitor de cámara IP remoto sin port-forwarding via Supabase Storage
  - Multi-cuenta: usuario principal + cuidadores vinculados
  - Persistencia local (SharedPreferences) + nube (Supabase PostgREST)
  - Sistema de puntos KOA Puntos con tienda de recompensas

4. BASE DE DATOS — SUPABASE POSTGRESQL
================================================================================

  URL del proyecto : https://ujbqnsdznvjjrqbrguyx.supabase.co
  Motor            : PostgreSQL (gestionado por Supabase)
  Seguridad        : Row Level Security (RLS) en todas las tablas

--------------------------------------------------------------------------------
4.1 TABLAS PRINCIPALES
--------------------------------------------------------------------------------

  auth.users            → Tabla nativa de Supabase Auth
  public.users          → Perfil extendido (id, email, full_name)
  public.face_biometrics → Vectores faciales JSONB (id, user_id, face_encoding)
  public.baby_profiles  → Perfiles de bebés (nombre, fecha nac., género, foto)
  public.feeding_entries → Tomas registradas (tipo, cantidad, givenBy)
  public.medical_appointments → Citas médicas programadas
  public.medicines       → Medicamentos con horarios (JSONB times[])
  public.vaccine_records → Cartilla de vacunación + refuerzos
  public.sleep_sessions  → Sesiones de sueño (inicio, fin, duración)
  public.diary_milestones → Hitos del diario con fotos
  public.camera_configs  → Configuración cámaras IP por usuario
  public.camera_streams  → Estado en tiempo real de cámaras (heartbeat)
  public.ptz_commands    → Cola de comandos PTZ remotos
  public.family_links    → Vínculos usuario principal ↔ cuidadores

--------------------------------------------------------------------------------
4.2 FUNCIONES POSTGRESQL
--------------------------------------------------------------------------------

  handle_new_user()           → Trigger: crea public.users al registrarse
  update_updated_at_column()  → Trigger: actualiza updated_at en UPDATE
  clean_old_ptz_commands()    → RPC: elimina comandos PTZ >5 min de antigüedad
  is_family_member(owner_id)  → Función RLS: verifica si usuario es cuidador

--------------------------------------------------------------------------------
4.3 POLÍTICAS RLS (Patrón general)
--------------------------------------------------------------------------------

  SELECT : auth.uid() = user_id OR is_family_member(user_id)
  INSERT : auth.uid() = user_id OR is_family_member(user_id)
  UPDATE : auth.uid() = user_id
  DELETE : auth.uid() = user_id

--------------------------------------------------------------------------------
4.4 SUPABASE STORAGE — BUCKETS
--------------------------------------------------------------------------------

  baby-photos        → Fotos de perfil de bebés (públicas)
  milestone-photos   → Fotos de hitos del diario (públicas)
  camera-streams     → Frames JPEG de cámaras (URLs firmadas 5 min)

5. SERVICIOS Y APIS
================================================================================

--------------------------------------------------------------------------------
5.1 AuthService (lib/services/auth_service.dart)
--------------------------------------------------------------------------------
  signUp(email, password, fullName)     → Registro Supabase Auth
  signIn(email, password)               → Login con JWT
  signInWithFace(faceEncoding)          → Login biométrico (coseno ≥ 0.75)
  signOut()                             → Cierre de sesión
  resetPassword(email)                  → Email de recuperación
  updatePassword(newPassword)           → Actualizar contraseña
  registerFaceBiometric(encoding)       → Guardar vector facial
  deleteAccount()                       → Eliminación completa (5 pasos)
  authStateChanges                      → Stream<AuthState>

--------------------------------------------------------------------------------
5.2 FaceEmbeddingService (lib/services/face_embedding_service.dart)
--------------------------------------------------------------------------------
  Modelo        : MobileFaceNet (assets/models/mobilefacenet.tflite, ~5 MB)
  Input tensor  : [1, 112, 112, 3] float32, normalizado [-1, 1]
  Output tensor : [1, 192] float32 L2-normalizado
  initialize()                          → Carga modelo TFLite
  generateEmbedding(bytes, faceBounds)  → Pipeline 7 pasos → List<double>
  cosineSimilarity(a, b)                → Similitud coseno [0.0, 1.0]
  Umbral autenticación                  : 0.75 (75%)

--------------------------------------------------------------------------------
5.3 CameraRelayService (lib/services/camera_relay_service.dart)
--------------------------------------------------------------------------------
  Singleton. Polling cada 500ms (2fps por defecto).
  getRemoteCameras()                    → Lista cámaras disponibles
  startPolling(cameraId, fps)           → Inicia polling de frames
  stopPolling()                         → Detiene polling
  sendPTZCommand(cameraId, command)     → Inserta en ptz_commands
  frameStream                           → Stream<Uint8List> frames JPEG
  stateStream                           → Stream<RemoteCameraState>
  Heartbeat timeout                     : 30 segundos

--------------------------------------------------------------------------------
5.4 CaregiverAccountService (lib/services/caregiver_account_service.dart)
--------------------------------------------------------------------------------
  createCaregiverAccount(name, email, password, role)
      → HTTP POST /auth/v1/signup (sin reemplazar sesión activa)
      → INSERT family_links {owner_user_id, caregiver_user_id, role}
  getOwnerUserId()      → owner_user_id si es cuidador, null si es principal
  isCaregiver()         → bool
  getCaregivers()       → List<FamilyLink>
  removeCaregiver()     → DELETE family_links
  autoLinkOnLogin()     → Auto-vincula al login si metadata tiene is_caregiver=true

--------------------------------------------------------------------------------
5.5 KoaPointsService (lib/services/koa_points_service.dart)

  Tabla de canjes:

--------------------------------------------------------------------------------
5.8 Home Bridge (home_bridge/bridge.py) — Python
--------------------------------------------------------------------------------
  Versión     : KOA Home Bridge v1.2
  Dependencias: opencv-python, requests
  Funciones:
    SupabaseREST     → Cliente HTTP sin SDK (sign_in, upsert, select, upload)

    Timeout RTSP     : 8 segundos (era 30s)
    JPEG quality     : 70% (max 150 KB por frame)
    Heartbeat        : cada 10 segundos
    Reconnect delay  : 3 segundos

6. FLUJO DE AUTENTICACIÓN
================================================================================

  6.1 REGISTRO NUEVO USUARIO
  ──────────────────────────
  1. Usuario llena nombre, email, contraseña → AuthService.signUp()
  2. Supabase crea auth.users → trigger handle_new_user() crea public.users
  3. App pregunta: "¿Agregar cuidador?" → CaregiverAccountService.createCaregiverAccount()
  4. Cuidador creado via HTTP POST sin afectar sesión activa
  5. family_links vincula ambas cuentas
  6. Navega a ProfileSelectionPage

  6.2 LOGIN CON EMAIL
  ───────────────────
  1. AuthService.signIn(email, password) → JWT session
  2. clearEffectiveUserId() → resetea caché
  3. CaregiverAccountService.autoLinkOnLogin() → auto-vincula si es cuidador
  4. getEffectiveUserId() detecta si es cuidador → usa owner_user_id

  6.3 LOGIN FACIAL
  ────────────────
  1. Cámara captura frame → ML Kit detecta rostro
  2. FaceEmbeddingService.generateEmbedding() → vector 192D
  3. AuthService.signInWithFace() → SELECT face_biometrics
  4. Similitud coseno con todos los vectores → acepta si ≥ 0.75

  6.4 RECUPERACIÓN DE CONTRASEÑA
  ──────────────────────────────
  1. Usuario toca "¿Olvidaste tu contraseña?"
  2. Ingresa email (pre-llenado si ya estaba escrito)
  3. AuthService.resetPassword(email) → supabase.auth.resetPasswordForEmail()
  4. Supabase envía correo con link de reseteo
  5. Usuario sigue el link → crea nueva contraseña

7. MONITOR DE CÁMARA REMOTA
================================================================================

  Arquitectura sin port-forwarding:

  [Cámara IP TV-628]
      │ RTSP (TCP, timeout 8s)
      ▼
  [PC Local — bridge.py]
      │ Captura frame → resize 640px → JPEG 70%
      │ POST /storage/v1/object/camera-streams/{userId}/{camId}/latest.jpg
      │ POST /rest/v1/camera_streams  (UPSERT: URL firmada + heartbeat)
      ▼
  [Supabase Storage + PostgreSQL]
      │ Polling cada 500ms
      ▼
  [Flutter App — CameraRelayService]
      │ SELECT camera_streams
      │ HTTP GET frame_url (firmada 5 min)
      │ Stream<Uint8List> → Image.memory()
      ▼
  [Pantalla del usuario — en cualquier parte del mundo]

  Control PTZ:
  [App] INSERT ptz_commands → [Bridge] SELECT ptz_commands → ONVIF/SOAP → Cámara

8. SISTEMA DE CUIDADORES (family_links)
================================================================================

  Tabla family_links:
    owner_user_id    → UUID del usuario principal
    caregiver_user_id → UUID del cuidador
    caregiver_name   → Nombre del cuidador
    role             → Mamá / Papá / Abuelo/a / Niñera / Otro
    linked_at        → Timestamp del vínculo

  effectiveUserId (lib/config/supabase_client.dart):
    - Cacheado en memoria (_cachedEffectiveUserId)
    - Si usuario es cuidador → retorna owner_user_id
    - Si usuario es principal → retorna su propio ID
    - Se limpia al hacer logout (clearEffectiveUserId())

  givenBy (quién dio la toma):
    - FeedingEntry.givenBy       → nombre del autenticado al registrar toma
    - MedicineDoseConfirmation   → nombre al presionar "Confirmar toma"
    - Se obtiene de supabase.auth.currentUser.userMetadata['full_name']
    - Fallback: parte del email antes del @

                 y establecer _hasNavigated=true antes de navegar

  BUG-04  Código muerto en AuthService.signInWithFace()
          Causa: if (userData == null) tras .single() (siempre non-null)
          Fix  : Eliminar comprobación redundante

  MEJORA-01  Home Bridge RTSP timeout 30s → 8s + TCP transport
  MEJORA-02  Auto-detección IP de cámara al cambiar por DHCP
  MEJORA-03  effectiveUserId para soporte multi-cuidador
