A.1  SUPABASE AUTH API  (REST v1)
--------------------------------------------------------------------------------
  URL base : https://ujbqnsdznvjjrqbrguyx.supabase.co/auth/v1/
  SDK      : supabase_flutter (Flutter) | requests HTTP directo (Python Bridge)

  Endpoints principales
  ┌─────────────────────────────────────────────────┬────────────────────────────┐
  │ Acción                                          │ Método / Ruta              │
  ├─────────────────────────────────────────────────┼────────────────────────────┤
  │ Registro de usuario (email + contraseña)        │ POST /auth/v1/signup       │
  │ Inicio de sesión (email + contraseña)           │ POST /auth/v1/token        │
  │                                                 │   ?grant_type=password     │
  │ Cierre de sesión                                │ POST /auth/v1/logout       │
  │ Recuperar contraseña (envío de email)           │ POST /auth/v1/recover      │
  │ Actualizar atributos de usuario                 │ PUT  /auth/v1/user         │
  │ Escucha de cambios de sesión (stream)           │ supabase.auth.onAuthStateChange │
  └─────────────────────────────────────────────────┴────────────────────────────┘

  Archivo de implementación (Flutter):
    lib/services/auth_service.dart
      - signUp()          → supabase.auth.signUp(email, password, data:{full_name})
      - signIn()          → supabase.auth.signInWithPassword(email, password)
      - signOut()         → supabase.auth.signOut()
      - resetPassword()   → supabase.auth.resetPasswordForEmail(email)
      - updatePassword()  → supabase.auth.updateUser(UserAttributes)
      - authStateChanges  → supabase.auth.onAuthStateChange  (Stream<AuthState>)

  Implementación Python (Home Bridge):
    home_bridge/bridge.py  — clase SupabaseREST.sign_in()
      POST /auth/v1/token?grant_type=password
      Body: { "email": "...", "password": "..." }
      Respuesta: { "access_token": "...", "user": { "id": "...", ... } }

  Autenticación Facial (custom, sin endpoint dedicado):
    lib/services/auth_service.dart — signInWithFace()
      1. SELECT face_biometrics WHERE user_id = currentUserId
      2. Calcula similitud coseno contra cada vector almacenado
      3. Umbral de aceptación: 75% (threshold = 0.75)
      4. Obtiene email del usuario desde tabla users
      5. Reutiliza la sesión JWT activa

A.2  SUPABASE POSTGREST API  (REST v1)
--------------------------------------------------------------------------------
  URL base : https://ujbqnsdznvjjrqbrguyx.supabase.co/rest/v1/
  Headers requeridos:
    apikey        : <supabase_anon_key>
    Authorization : Bearer <access_token>
    Content-Type  : application/json

  Operaciones CRUD implementadas por tabla
  (Archivo principal: lib/services/supabase_service.dart)

  ── face_biometrics ──────────────────────────────────────────────────────────
    SELECT  user_id, face_encoding          → auth_service.dart (login facial)
    INSERT  user_id, face_encoding, device_id → registerFaceBiometric()
    SELECT  id, face_encoding, device_id, registered_at → getUserFaceBiometrics()
    DELETE  WHERE id = ? AND user_id = ?    → deleteFaceBiometric()
    DELETE  WHERE user_id = ?               → deleteAccount() paso 1

  ── baby_profiles ────────────────────────────────────────────────────────────
    SELECT  * WHERE user_id = ? ORDER BY created_at DESC   → getBabyProfiles()
    INSERT  {name, birthdate, gender, photo_url, user_id}  → createBabyProfile()
    UPDATE  SET ... WHERE id = ? AND user_id = ?           → updateBabyProfile()
    DELETE  WHERE id = ? AND user_id = ?                   → deleteBabyProfile()

  ── feeding_entries ──────────────────────────────────────────────────────────
    SELECT  * WHERE baby_id = ? AND user_id = ? ORDER BY timestamp DESC
    INSERT  {baby_id, user_id, type, amount, notes, timestamp}
    DELETE  WHERE id = ? AND user_id = ?

  ── medical_appointments ─────────────────────────────────────────────────────
    SELECT  * WHERE baby_id = ? AND user_id = ? ORDER BY date ASC
    INSERT  {baby_id, user_id, title, doctor_name, date, notes, completed}
    UPDATE  SET ... WHERE id = ? AND user_id = ?
    DELETE  WHERE id = ? AND user_id = ?

  ── medicines ────────────────────────────────────────────────────────────────
    SELECT  * WHERE baby_id = ? AND user_id = ? ORDER BY created_at DESC
    INSERT  {baby_id, user_id, name, dosage, frequency, times, start_date, end_date}
    UPDATE  SET ... WHERE id = ? AND user_id = ?
    DELETE  WHERE id = ? AND user_id = ?

  ── vaccine_records ──────────────────────────────────────────────────────────
    SELECT  * WHERE baby_id = ? AND user_id = ? ORDER BY created_at DESC
    UPSERT  {baby_id, user_id, vaccine_id, vaccine_name, applied, date_applied}

  ── sleep_sessions ───────────────────────────────────────────────────────────
    SELECT  * WHERE baby_id = ? AND user_id = ? ORDER BY start_time DESC
    INSERT  {baby_id, user_id, start_time, end_time, duration_minutes}
    UPDATE  SET ... WHERE id = ? AND user_id = ?
    DELETE  WHERE id = ? AND user_id = ?

  ── diary_milestones ─────────────────────────────────────────────────────────
    SELECT  * WHERE baby_id = ? AND user_id = ? ORDER BY date DESC
    INSERT  {baby_id, user_id, title, description, date, photo_url}
    UPDATE  SET ... WHERE id = ? AND user_id = ?
    DELETE  WHERE id = ? AND user_id = ?

  ── camera_configs ───────────────────────────────────────────────────────────
    SELECT  * WHERE user_id = ? ORDER BY created_at DESC
    INSERT  {user_id, name, host, protocol, rtsp_port, rtsp_path, ...}
    UPDATE  SET ... WHERE id = ? AND user_id = ?
    DELETE  WHERE id = ? AND user_id = ?

  ── camera_streams ───────────────────────────────────────────────────────────
    (Gestionada principalmente desde Home Bridge + CameraRelayService)
    SELECT  * WHERE user_id = ? ORDER BY camera_name          → getRemoteCameras()
    SELECT  * WHERE user_id = ? AND camera_id = ? LIMIT 1     → findRemoteCamera()
    SELECT  * WHERE user_id = ? AND is_online = true LIMIT 1  → fallback automático
    UPSERT  {user_id, camera_id, camera_name, is_online, last_frame_url,
             last_heartbeat, fps}  ON CONFLICT(user_id, camera_id) MERGE
    UPDATE  SET is_online=false WHERE user_id=? AND camera_id=?

  ── ptz_commands ─────────────────────────────────────────────────────────────
    INSERT  {user_id, camera_id, command}                     → sendPTZCommand()
    SELECT  * WHERE user_id=? AND camera_id=? AND executed=false
             ORDER BY created_at ASC LIMIT 5                  → bridge.py polling
    UPDATE  SET executed=true WHERE id=?                      → tras ejecutar PTZ

  ── users ────────────────────────────────────────────────────────────────────
    SELECT  email WHERE id = ?    → auth_service.dart (login facial paso 3)

  ── Tablas referenciadas en deleteAccount() (limpieza en cascada): ───────────
    activity_logs, feeding_logs, sleep_logs, health_records,
    milestones, growth_records, subscriptions

  Operaciones Python (home_bridge/bridge.py — clase SupabaseREST):
    storage_upload(bucket, path, data_bytes)
      POST /storage/v1/object/{bucket}/{path}
      Header: x-upsert: true
      Body: bytes JPEG
      Ruta: {userId}/{cameraId}/latest.jpg

    storage_signed_url(bucket, path, expiresIn=300)
      POST /storage/v1/object/sign/{bucket}/{path}
      Body: { "expiresIn": 300 }

    ensure_bucket(bucket)
      GET  /storage/v1/bucket/{bucket}   (verificar existencia)
      POST /storage/v1/bucket            (crear si no existe)

A.6  RECONOCIMIENTO FACIAL ON-DEVICE (ML Kit + TFLite)
--------------------------------------------------------------------------------
  Tecnología  : Google ML Kit Face Detection + MobileFaceNet (TFLite)
  Tipo        : 100% local, sin API remota en tiempo real
  Archivo     : lib/services/face_embedding_service.dart (TFLite)
                lib/services/auth_service.dart (comparación de vectores)

  Flujo de operación:
    1. Captura imagen del rostro con cámara del dispositivo
    2. Google ML Kit detecta landmarks y recorta el rostro
    3. MobileFaceNet (modelo .tflite) genera vector de 128/512 dimensiones
    4. Vector se almacena en Supabase: tabla face_biometrics (JSONB)
    5. En login facial: se obtienen todos los vectores de la BD
    6. Se calcula similitud de coseno entre el vector capturado y cada almacenado
    7. Si similitud >= 0.75 → autenticación exitosa

  Fórmula de similitud de coseno (auth_service.dart):
    similitud = (v1 · v2) / (|v1| × |v2|)
    Umbral aceptado: 0.75 (75%)

A.7  ONVIF PTZ (cámaras IP TV-628)
--------------------------------------------------------------------------------
  Protocolo : ONVIF/SOAP sobre HTTP
  URL       : http://{host}:{onvif_port}/onvif/ptz_service
  Archivo   : home_bridge/bridge.py — métodos _execute_ptz(), _ptz_move_soap(),
                                       _ptz_stop_soap()

  Comandos SOAP implementados:
    ContinuousMove (PanTilt + Zoom)  → comandos: left, right, up, down,
                                                  zoom_in, zoom_out
    Stop (PanTilt + Zoom)            → comando: stop

  Parámetros de velocidad:
    left  → x=-0.5, y=0.0,  zoom=0.0
    right → x=+0.5, y=0.0,  zoom=0.0
    up    → x=0.0,  y=+0.5, zoom=0.0
    down  → x=0.0,  y=-0.5, zoom=0.0
    zoom+ → x=0.0,  y=0.0,  zoom=+0.5
    zoom- → x=0.0,  y=0.0,  zoom=-0.5
  Tras cada movimiento se envía Stop automáticamente (0.5s después).

B.3  SEGURIDAD: ROW LEVEL SECURITY (RLS)
--------------------------------------------------------------------------------
  Todas las tablas tienen RLS habilitado con el mismo patrón:

    SELECT → USING (auth.uid() = user_id)
    INSERT → WITH CHECK (auth.uid() = user_id)
    UPDATE → USING (auth.uid() = user_id)
    DELETE → USING (auth.uid() = user_id)

  Excepción — public.users:
    SELECT/UPDATE → USING (auth.uid() = id)
    INSERT        → WITH CHECK (auth.uid() = id)

  El campo user_id en todas las tablas de datos del bebé actúa como
  filtro de aislamiento total: un usuario nunca puede ver ni modificar
  datos de otro usuario, incluso si conoce el UUID.

B.4  TRIGGERS Y FUNCIONES AUTOMÁTICAS
--------------------------------------------------------------------------------
  update_updated_at_column()   (Función PL/pgSQL)
    Actualiza la columna updated_at con NOW() antes de cada UPDATE.
    Triggers asignados:
      update_users_updated_at         → BEFORE UPDATE ON public.users
      update_baby_profiles_updated_at → BEFORE UPDATE ON public.baby_profiles

  handle_new_user()   (Función PL/pgSQL — SECURITY DEFINER)
    Se ejecuta automáticamente cuando se crea un usuario en auth.users.
    Inserta en public.users:
      { id: NEW.id, email: NEW.email,
        full_name: COALESCE(raw_user_meta_data->>'full_name', 'Usuario') }
    Trigger: on_auth_user_created → AFTER INSERT ON auth.users

  clean_old_ptz_commands()   (Función RPC)
    Elimina registros de ptz_commands donde created_at < NOW() - 5 minutos.
    SECURITY DEFINER para poder borrar sin RLS.
    Llamada periódica desde home_bridge/bridge.py cada 60 segundos.

B.6  FLUJO DE DATOS — CÁMARA REMOTA (fuera de red local)
--------------------------------------------------------------------------------
  Arquitectura de relay sin port-forwarding:

    [Cámara IP TV-628]
         │ RTSP stream
         ▼
    [PC Local — home_bridge/bridge.py]
         │ OpenCV captura frames
         │ Redimensiona a 640px, JPEG quality=70 (máx 150 KB)
         │ POST /storage/v1/object/camera-streams/{userId}/{camId}/latest.jpg
         │ POST /rest/v1/camera_streams  (UPSERT: heartbeat + URL firmada)
         ▼
    [Supabase Storage + PostgreSQL]
         │ (polling cada 500ms por defecto, ajustable por fps)
         ▼
    [Flutter App — CameraRelayService]
         │ SELECT camera_streams WHERE user_id + camera_id
         │ HTTP GET frame_url  (URL firmada, válida 5min)
         │ Stream<Uint8List> frameStream → renderiza en widget Image.memory
         ▼
    [Usuario — pantalla del teléfono en cualquier parte del mundo]

  Control PTZ remoto:
    [App Flutter] → INSERT ptz_commands {command}
    [Bridge Python] → SELECT ptz_commands WHERE executed=false  (cada frame)
    [Bridge Python] → ONVIF SOAP → Cámara IP
    [Bridge Python] → UPDATE ptz_commands SET executed=true
